# Arène v2 : plan

Cadrage : `docs/specs/2026-11-17-arene-design.md` (sections marquées v2). Maquette : `docs/maquettes/arene-v2.html`.

**Appétit** : un lot. **No-gos** : pas de nouvelle action, pas de chat ni d'emote, pas de connexion permanente (WebSocket), pas d'animation hors de `/arene`. **Fondrière** : le rejeu côté client ; limite posée : une file d'actions et un instantané des PV par action, rien de plus.

## Tâches (un commit chacune, sur `feat/arena-v2`)

1. **Moteur** (`src/game/arena.ts`, test d'abord) : `ArenaInput` = l'Arène et ses actions ; +3 PA au début de chaque tour (plafond 6), bonus outsider calculé depuis les évolutions ; 2 potions au départ ; Parade encaissée = +1 PA (pas si percée) ; suppression des événements candidature / relance et du tour injouable ; chaque ligne du journal porte les PV après coup (`hp`). `startEnergy` → `startBonus`.
2. **Serveur** : `arene-actions.ts` (plus d'apps ni de relances, message « Pas assez de PA »), `actions.ts` (plus de « À toi de jouer » sur candidature), `server/arena.ts` (résumé sans « à court d'énergie »), notification de provocation sans `rusty`, cron et résultat alignés.
3. **Présence** : migration `Player.arenaSeenAt`, notée à chaque affichage de `/arene` ; pastille côté client (présent < 10 s, hors connexion via `navigator.onLine`).
4. **Rejeu et direct** (`ArenaStage.tsx`) : file des actions adverses non vues (stockage local par Arène), 1,5 s par action, PV pris dans l'instantané, journal qui se remplit, bandeau « Pendant ton absence » + « Passer », actions verrouillées pendant le rejeu ; rafraîchissement 3 s quel que soit le tour.
5. **Textes** : `/arene` (PA gardés / reçus, Parade +1 PA, potions, Botte trop chère, plus de « + Candidature »), carte de l'accueil, panneau de provocation, bandeau reçu, écran de l'intro, page de résultat.
6. `npm test`, lint, build ; parcours à deux navigateurs en local (rejeu, direct, Parade), mobile 390 px.
