# Quêtes v2 · plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Ranger les quêtes avec les actions vers le binôme, nommer les compagnons, rendre la Ménagerie accessible.

**Architecture:** Le nom vit sur la quête qui a donné le compagnon (`Quest.companionName`) ; le moteur expose
`companionLabel` et `checkCompanionName`. L'accueil remplace `QuestsCard` par `QuestBanner` (gauche) et
`QuestLine` + 4e action (carte du binôme).

**Spec:** `docs/specs/2026-11-18-quetes-design.md` §v2 · maquette v2 : https://claude.ai/artifact/86zZiZqnT4u6KJaabopjJG

## Global Constraints
- `COMPANION_NAME_MAX = 16` ; nom vide → nom de l'espèce (`COMPANION_NAMES[id].name`).
- Renommer : seulement un compagnon adopté par le joueur (filtre `receiverId`, `status: "VALIDATED"`, `companion`).
- Textes neutres en genre ; « d'Adrien » via `ofName`.

## Review Focus
1. Nom de 17 caractères ou fait d'espaces → refusé / remplacé par l'espèce.
2. Renommer le compagnon d'un autre joueur → refusé (aucune ligne mise à jour).
3. Bouton Quête quand une quête est en cours dans ce sens → grisé avec la raison, pas de lien.
4. Accueil sans binôme connecté → ni bandeau ni ligne, pas d'erreur.
5. Petits écrans (320 px) : 4 actions sur deux lignes sous 360 px, pas de débordement.
