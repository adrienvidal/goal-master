# Quêtes et compagnons · plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Un joueur lance une quête à l'autre ; validée, elle rapporte des XP aux deux et ouvre un coffre où le destinataire adopte un compagnon parmi trois.

**Architecture:** Moteur pur `src/game/quests.ts` (états, tirage, collection, XP) ; la table `Quest` stocke la quête, l'offre du coffre et le compagnon adopté ; l'XP et la collection se calculent. Actions serveur dans `src/app/quete-actions.ts`, écrans `/quete/nouvelle`, `/quete/[id]`, `/coffre`, `/menagerie`, carte sur l'accueil.

**Tech Stack:** Next.js App Router, Prisma 7 (adaptateur pg), Tailwind, Vitest.

**Spec:** `docs/specs/2026-11-18-quetes-design.md` · maquette validée : https://claude.ai/artifact/86zZiZqnT4u6KJaabopjJG (`docs/maquettes/quetes.html`)

## Global Constraints

- `XP_QUEST_DONE = 20` (destinataire), `XP_QUEST_GIVEN = 5` (donneur), hors plafond quotidien, comptés à `validatedAt`.
- `QUEST_TEXT_MAX = 120` caractères, texte obligatoire (après `trim`).
- `CHEST_OFFER_SIZE = 3` ; offre = compagnons ni possédés ni proposés dans un coffre non ouvert du même joueur.
- Une quête en cours (`OPEN` ou `DONE`) au plus par sens (donneur → destinataire).
- Une validation ne se retire jamais. L'énergie de l'Arène ne vient jamais des quêtes.
- Catalogue : `cat`, `dog`, `fox`, `owl`, `rabbit`, `dragon` (Chat, Chien, Renard, Hibou, Lapin, Petit dragon).
- Notifications de la catégorie `quests`, `capped: false`.
- Jours à minuit Paris ; textes en français, sans nom d'entreprise.
- Commits en anglais, impératif, préfixe `feat:`/`test:`… ; branche `feat/quetes` depuis `dev`.

## Review Focus

1. Deux validations simultanées (double clic) : un seul coffre, une seule offre → mise à jour conditionnelle `where: { status: "DONE" }`.
2. Adopter un compagnon hors de l'offre (requête forgée) → refusé côté serveur.
3. Destinataire qui valide sa propre quête, donneur qui la marque faite → refusé (filtre `giverId` / `receiverId`).
4. Collection complète ou un seul restant → pas de coffre bloquant / compagnon donné d'office.
5. Lien `javascript:` ou non-URL → refusé ; seuls `http:` et `https:`.

### Task 1: Moteur des quêtes

**Files:** Create `src/game/quests.ts`, `src/game/quests.test.ts`

**Interfaces — Produces:**
- `type QuestStatus = "OPEN" | "DONE" | "VALIDATED" | "CANCELLED"`
- `type QuestRow = { id; giverId; receiverId; text; link: string | null; status: QuestStatus; offer: string[]; companion: string | null; createdAt: Date; doneAt: Date | null; validatedAt: Date | null; closedAt: Date | null }`
- constantes `XP_QUEST_DONE`, `XP_QUEST_GIVEN`, `QUEST_TEXT_MAX`, `CHEST_OFFER_SIZE`, `COMPANION_IDS` (`as const`), `type CompanionId`
- `openQuest(giverId, receiverId, quests): QuestRow | null` — `OPEN` ou `DONE` dans ce sens, la plus récente
- `checkQuestText(raw: string): { ok: true; text: string } | { ok: false; error: string }`
- `checkLink(raw: string): { ok: true; link: string | null } | { ok: false; error: string }` (vide → `null`)
- `ownedCompanions(playerId, quests): CompanionId[]` — `companion` des quêtes `VALIDATED` reçues, ordre d'adoption
- `pendingChest(playerId, quests): QuestRow | null` — validée reçue, `offer.length > 0`, `companion === null`, la plus ancienne
- `drawOffer(playerId, quests, random = Math.random): CompanionId[]` — tirage uniforme sans remise de `CHEST_OFFER_SIZE` parmi le reste (exclut possédés et offres des coffres en attente)
- `questXp(playerId, quests, at?: Date): number` — 20 par quête validée reçue, 5 par quête validée donnée, `validatedAt <= at` si `at`
- `questsGivenValidated(playerId, quests): number`

### Task 5: Actions serveur

**Files:** Create `src/app/quete-actions.ts`

**Interfaces — Produces** (toutes `Promise<QuestResult>`, `QuestResult = { ok: true; id?: string } | { ok: false; error: string }`) :
- `launchQuest(text)` — refuse si `openQuest(me, partner)` existe (« Nicolas a déjà une quête de ta part. ») ; notifie `quest`.
- `markQuestDone(id, link)` — `updateMany where { id, receiverId: me, status: "OPEN" }` → `DONE`, `doneAt`, `link` ; notifie `quest-done`.
- `validateQuest(id)` — `updateMany where { id, giverId: me, status: "DONE" }` → `VALIDATED`, `validatedAt`, `offer = drawOffer(receiver)` ; si l'offre a 1 élément : `companion` posé d'office ; si le destinataire n'a pas de compagnon affiché et qu'un compagnon est posé, `Player.companion` aussi ; notifie `quest-end validated`.
- `refuseQuest(id)` — `DONE` → `OPEN`, `link` gardé ; notifie `quest-end` non validée.
- `cancelQuest(id)` — `giverId: me`, `status in OPEN|DONE` → `CANCELLED`, `closedAt` ; notifie `quest-cancel`.
- `adoptCompanion(questId, companion)` — `updateMany where { id, receiverId: me, status: "VALIDATED", companion: null, offer: { has: companion } }` ; si `count === 1`, `Player.companion = companion`.
- `showCompanion(companion)` — refuse si pas dans `ownedCompanions(me)`.
Chaque action `revalidatePath("/")`, notifications dans `after()`, comme `defi-actions.ts`.

- [ ] **Step 1:** Implémenter (le moteur porte la logique testée ; les gardes sont dans les `where`).
- [ ] **Step 2:** `npx tsc --noEmit` → OK ; commit `feat: add quest server actions`
